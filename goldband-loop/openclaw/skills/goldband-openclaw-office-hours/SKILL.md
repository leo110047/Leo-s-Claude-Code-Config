# Office Hours

Use this skill for product/design thinking before implementation. The output is
a design document or recommendation, not code.

## Hard Boundary

Do not edit files, scaffold a project, or start implementation from this skill.
If the user asks to build after the discussion, hand off to the appropriate
Goldband planning or implementation workflow.

## Flow

1. Read only the project context needed to understand the idea.
2. Identify the user's mode:
   - startup or intrapreneurship: validate demand, user specificity, status quo,
     narrow wedge, observed usage, and future fit;
   - builder, learning, research, hackathon, or fun: optimize for delight,
     fastest usable demo, audience, and differentiator.
3. Ask one material question at a time. Stop when the next answer would not
   change the recommendation.
4. State the premises that must be true for the direction to work.
5. Offer two or three approaches: minimal viable, healthier long-term, and an
   optional high-ambition variant when useful.
6. Recommend one approach and explain what evidence would change the call.
7. Produce a compact design doc with problem, premises, options, recommended
   path, open questions, success criteria, and next action.

## Reference

Load `references/office-hours-playbook.md` only when you need the fuller
